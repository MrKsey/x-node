Что делают приложения

Yggdrasil — это зашифрованная оверлейная IPv6-сеть. Она соединяет свои узлы, но сама по себе не маршрутизирует трафик в обычный интернет. Exit-узел — это шлюз, который этим занимается.

X-Node — exit-узел

Работает на сервере с Ubuntu или Debian. Принимает SOCKS5-запросы через Yggdrasil, проверяет список разрешённых клиентов, применяет квоты и отправляет трафик в интернет с сервера. Здесь же работают веб-интерфейс и, при желании, DNS-сервер Alfis для клиентов.

Y-Node — клиент

Android-приложение. Запускает узел Yggdrasil, создаёт системный VPN-интерфейс и направляет трафик выбранных приложений через туннель. Профиль exit-узла указывает, какой X-Node использовать для выхода в обычный интернет.

X-Node

Установка

Поддерживаются Ubuntu 24.04 и Debian 12. Запустите установщик от root:

sudo bash <(curl -fsSL https://raw.githubusercontent.com/MrKsey/x-node/main/install.sh)

Установщик добавляет Yggdrasil, X-Node и root-helper, записывает конфигурацию и печатает адрес веб-интерфейса и пароль администратора. Он также спрашивает, включать ли DNS-сервер, и создаёт первое приглашение. Учётные данные сохраняются в /root/x-node-credentials.txt.

Что он умеет

  • SOCKS5 поверх TCP и UDP, поэтому работают DNS и QUIC.
  • Регистрация клиентов по одноразовым приглашениям, QR-кодам и ссылкам.
  • Метки клиентов, доступ, дневные и месячные квоты, ограничения скорости.
  • Учёт трафика, который переживает перезапуски.
  • Автоматические публичные пиры Yggdrasil и пиры, закреплённые вручную.
  • Веб-интерфейс и полноценная командная строка.
  • Необязательный DNS-сервер Alfis для имён Yggdrasil.

Командная строка

Те же операции доступны в оболочке. Каждая команда принимает -config PATH.

  • x-node status — конфигурация и текущие счётчики.
  • x-node invite — новое приглашение, QR-код и ссылка.
  • x-node allow list, allow add, allow remove — список доступа.
  • x-node allow link ADDRESS — QR-код для уже разрешённого клиента.
  • x-node clients, x-node usage — кто подключён и сколько потратил.
  • x-node quota show, quota set, quota reset — лимиты.
  • x-node peers — состояние публичных пиров; peers refresh проверяет их заново.
  • x-node dns status, dns on, dns off — DNS-сервер.
  • x-node web url, web password — адрес панели и пароль.
  • x-node doctor — проверки установки с подсказками.
  • x-node update check, update upgrade — релизы.

Веб-интерфейс X-Node

Панель отдаётся по случайному пути и защищена входом. Адрес печатает x-node web url и установщик.

Дашборд

Сверху четыре счётчика: адрес Yggdrasil, число клиентов, трафик за сегодня и за этот месяц. Под ними — график трафика. Ниже две карточки: X-Node слева и Yggdrasil справа, а карточка DNS-сервер стоит прямо под Yggdrasil. Адрес Yggdrasil и peer link показаны в одну строку, без переноса; длинное значение можно прокрутить по горизонтали.

График трафика показывает 15 минут, 1 час, 6 часов или 24 часа. В карточке X-Node:

  • X-Node — состояние службы, порты SOCKS5 и API, режим доступа, лимиты подключений, UDP-ретранслятор, исходящий IPv6, пути.
  • Yggdrasil — версия, публичный ключ, записи маршрутизации, подсеть, пиры и peer link.
  • DNS-сервер — состояние Alfis, адрес прослушивания, пароль веб-интерфейса Alfis и ссылка, открывающая панель Alfis в новой вкладке.

Дальше идут System Info и Update, затем Quotas и Web interface, а таблица пиров закрывает страницу.

Клиенты

Зарегистрированные клиенты с адресом, именем устройства, версией приложения, живыми счётчиками TCP и UDP, трафиком и квотой. Шесть действий строки на десктопе располагаются в два ряда по три; на планшете таблица превращается в карточки.

  • Edit — метка, заметки и лимиты клиента.
  • QR / link — показать код, который снова добавит этот exit на телефон.
  • New token — аннулировать старый API-токен и выдать новый.
  • Disconnect all — закрыть открытые сессии TCP и UDP.
  • Suspend — оставить клиента в списке, но отказывать в новых подключениях.
  • Remove — убрать адрес из списка доступа.

Приглашения

Приглашение — одноразовый секрет. Укажите, сколько устройств могут им воспользоваться и сколько оно действует, затем покажите QR-код или скопируйте ссылку yggnode://. Токен хранится на сервере, поэтому код можно показать снова позже.

Конфигурация и журналы

Configuration показывает config.json и yggdrasil.conf. Редактор проверяет файл перед сохранением и оставляет резервную копию. Изменения слушателей требуют перезапуска; кнопки есть на дашборде.

Logs показывает последние строки службы. Wrap lines включён по умолчанию; выключите его, чтобы читать трассировку без переносов. Auto refresh опрашивает журнал каждые три секунды. Пункт Help в меню слева под Logs открывает это руководство в новой вкладке.

Настройки X-Node

Каждая карточка сохраняет только свои поля, поэтому изменение в одной форме никогда не перезаписывает другую.

DNS-сервер

X-Node может запускать Alfis отдельной службой x-node-dns.service. Он отвечает на DNS-запросы клиентов exit-узла и доступен только через Yggdrasil, по адресу Yggdrasil сервера.

На что отвечает Alfis

  • Имена внутри Yggdrasil, включая .ygg, из собственной распределённой зоны.
  • Обычные имена, пересылаемые настроенным вышестоящим резолверам (по умолчанию два адреса Quad9).
  • Имена кэшируются в памяти; лимит кэша по умолчанию — 100 МБ.

Как включить

  1. Откройте Settings → DNS server, включите тумблер и нажмите Save.
  2. Сервер сгенерирует пароль веб-интерфейса Alfis, если он пуст, запишет /etc/x-node/alfis.conf, установит unit и запустит его. Если Alfis ещё не установлен, X-Node скачает и поставит его сам.
  3. Карточка на дашборде переключится в running. Кнопка Open Alfis web UI откроет http://ADDRESS:8082/ в новой вкладке; войдите с паролем из карточки.

Тот же переключатель есть в оболочке: sudo x-node dns on и sudo x-node dns off. Выключение останавливает unit, но сохраняет пароль и данные зоны.

Архивы релизов содержат Alfis со встроенным веб-интерфейсом. Если вместо него установлен nogui-бинарник с upstream, DNS продолжит работать, но unit не передаст --web-ui, и ссылка на панель будет скрыта.

Что видят клиенты

Когда сервер включён, Y-Node узнаёт о нём от exit-узла и показывает его в Settings → DNS → Available servers с пометкой DNS from exit node. Адрес — это адрес Yggdrasil узла X-Node и порт 53, если установщик не выбрал другой порт.

Оператор exit-узла может сделать его сервером по умолчанию для профиля тумблером DNS exit node в настройках exit-узла Y-Node. Тогда сервер появляется в IN USE с замком: пока тумблер включён, удалить его вручную нельзя.

Порты и файлы

  • dns.listen — адрес резолвера, по умолчанию адрес Yggdrasil на порту 53.
  • dns.webListen — веб-интерфейс Alfis, по умолчанию адрес Yggdrasil на порту 8082. Он говорит по обычному HTTP и не выставлен в обычный интернет.
  • /etc/x-node/alfis.conf — сгенерированная конфигурация Alfis. Редактируйте её через вкладку Configuration или настройки; ручные правки заменяются при следующей синхронизации.
  • /var/lib/x-node-dns — состояние Alfis: ключи, данные зоны и кэш.
  • dns.forwarders — вышестоящие резолверы для обычных имён.

Y-Node

Y-Node — это Android-клиент. Установите APK под архитектуру устройства (arm64-v8a для большинства телефонов, armeabi-v7a для старых 32-битных устройств), откройте приложение и разрешите VPN.

Вкладки

  • Tunnel — подключение и отключение, ваш адрес и ключ Yggdrasil, текущий трафик, задержка, карточка exit-узла и состояние переключения.
  • Peers — используемые пиры, пул замены, поиск пиров с ранжированием по задержке и ручные адреса пиров.
  • Address book — каталог сайтов и сервисов Yggdrasil с поиском и своими записями.
  • Apps — маршрутизация по приложениям: какие приложения идут через туннель, а какие остаются в мобильной сети.
  • Settings — подключение, DNS, сеть, питание, журналы, оформление, обновления и сведения.

Добавление exit-узла

  1. На X-Node создайте приглашение: sudo x-node invite или страница Invites.
  2. В Y-Node откройте карточку exit-узла и нажмите Add an exit node.
  3. Отсканируйте QR-код, вставьте ссылку yggnode:// или введите адрес и порты вручную.
  4. Активируйте профиль. Приложение зарегистрирует устройство, получит API-токен и проверит exit.

Профиль можно добавить и как обычный SOCKS5-прокси, указав только адрес Yggdrasil и порт. Такой профиль помечается SOCKS5; позже его можно расширить приглашением или токеном.

Карточка exit-узла

Карточка показывает состояние — Online, Connecting, Degraded, Direct fallback, Not allowed, Unreachable — и время отклика. Здесь же видны квоты и ограничения скорости, о которых сообщил сервер, и состояние IPv6 на exit-узле.

Несколько профилей образуют список переключения: когда активный перестаёт отвечать, приложение пробует следующий. Профиль можно проверить по требованию кнопкой Check now.

Журналы

Settings → Logs открывает журнал событий приложения и узла Yggdrasil. Там же журнал можно скопировать или отправить для отчёта об ошибке. Этапы подключения — разрешение, туннель, пиры, первый ответ — видны на вкладке Tunnel, пока приложение подключается.

DNS в Y-Node

Settings → DNS решает, как телефон разрешает имена, пока туннель поднят.

РежимПоведение
YggdrasilЗапросы идут на DNS-серверы, доступные внутри Yggdrasil. Имена .ygg разрешаются, а DNS-сервер exit-узла может разрешать и обычные имена. Выберите этот режим, чтобы пользоваться DNS-сервером exit-узла.
SystemТелефон использует собственный DNS. Имена .ygg по-прежнему разрешает встроенный резолвер; обычные имена идут на резолвер мобильной сети или Wi-Fi.

IN USE и Available servers

IN USE перечисляет серверы, которые действительно опрашиваются, по порядку. Available servers содержит пресеты и серверы, найденные в сети. Add server принимает IPv6-адрес внутри Yggdrasil.

Сервер может пометиться Not working: приложение не получило от него ответ. Проверка идёт в фоне и не блокирует туннель.

DNS от exit-узла

Когда X-Node запускает DNS-сервер, Y-Node автоматически добавляет его в Available servers с пометкой DNS from exit node. Это адрес Yggdrasil exit-узла на порту 53.

Тумблер DNS exit node в настройках профиля exit-узла помещает этот сервер в IN USE и запирает его значком замка: пока тумблер включён, сервер нельзя удалить вручную. Выключите тумблер, чтобы управлять списком самостоятельно.

DNS-серверы exit-узла

В настройках профиля exit-узла Exit DNS servers — это резолверы, которыми телефон пользуется, пока трафик идёт через этот exit. Они отделены от режима DNS: режим решает, используется ли Yggdrasil DNS вообще, а список exit определяет, к каким адресам обращаться. Сервер, полученный от exit-узла, добавляется в этот список и может храниться для каждого профиля.

Как DNS находит exit

DNS-сервер объявляет сам exit-узел, поэтому между двумя машинами ничего не нужно копировать вручную.

Проверка

  1. На X-Node x-node dns status сообщает, что сервер включён и unit активен.
  2. Карточка DNS на дашборде показывает running, а веб-интерфейс Alfis открывается по кнопке.
  3. В Y-Node профиль exit-узла активен, и карточка показывает Online.
  4. Режим DNS — Yggdrasil, а сервер виден в Available servers с пометкой DNS from exit node.
  5. Включите DNS exit node в настройках exit-узла, чтобы он появился в IN USE.
  6. Откройте сайт .ygg и обычный сайт, чтобы проверить оба пути.

Решение проблем

Карточка DNS показывает stopped

  • Helper не установлен: карточка показывает ошибку. Запустите install.sh ещё раз.
  • Alfis отсутствует: карточка сообщает Alfis is not installed. Установщик добавляет бинарник; запустите его заново или включите DNS в настройках — X-Node скачает Alfis сам.
  • Unit упал: journalctl -u x-node-dns -n 50 покажет причину. Порт 53 может быть занят другим резолвером.

Клиент не может зарегистрироваться

  • Приглашение использовано или истекло: создайте новое.
  • Телефон не подключён к Yggdrasil: проверьте вкладку Tunnel.
  • Exit-узел недоступен: проверьте peer link и x-node status.
  • Регистрация отключена в X-Node Settings → Access.

Обычные имена не разрешаются

  • Режим DNS — System: переключите на Yggdrasil, чтобы использовать резолвер exit-узла.
  • DNS-сервер exit-узла выключен или его форвардеры недоступны.
  • Сервера нет в IN USE: добавьте его или включите тумблер exit-узла.
  • UDP заблокирован на пути: X-Node Settings → UDP relay должен быть включён.

Панель не открывается

  • Используйте точный адрес из x-node web url, включая случайный путь.
  • Публичный URL зависит от настроек nginx и файрвола в установщике.
  • Слишком много неудачных входов блокируют адрес на 15 минут по умолчанию.

Безопасность

  • Приватный ключ Yggdrasil — это идентичность узла. Любой, у кого он есть, может пользоваться адресом; не кладите его в общие резервные копии.
  • Приглашение — одноразовый секрет. Относитесь к QR-коду как к паролю и отзывайте неиспользованные приглашения.
  • Открытый режим отключает список доступа и квоты. Не включайте его на публичном exit-узле.
  • У веб-интерфейса Alfis свой пароль. Он хранится в dns.webPassword и показан на дашборде; смените его при утечке.
  • Панель защищена входом и случайным путём URL, но не заменяет HTTPS. Публикуйте её через nginx с сертификатом, если она доступна из интернета.
  • Yggdrasil скрывает трафик от промежуточных узлов, но exit-узел видит назначения. Запускайте свой exit или доверяйте его оператору.
