X-Node and Y-Node

A short guide to the exit node, the Android client, and the DNS server they can share.

What the two apps do

Yggdrasil is an encrypted IPv6 overlay network. It connects its own nodes, but it does not route traffic to the ordinary Internet by itself. An exit node is the gateway that does that.

X-Node — the exit node

Runs on an Ubuntu or Debian server. It accepts SOCKS5 requests over Yggdrasil, checks the allowlist, applies quotas, and sends the traffic to the Internet from the server. It also runs the web interface and can run the Alfis DNS server for its clients.

Y-Node — the client

An Android app. It runs a Yggdrasil node, creates the system VPN interface, and sends the traffic of the selected apps through the tunnel. An exit profile tells it which X-Node to use for the regular Internet.

X-Node

Installing

Ubuntu 24.04 and Debian 12 are supported. Run the installer as root:

sudo bash <(curl -fsSL https://raw.githubusercontent.com/MrKsey/x-node/main/install.sh)

The installer adds Yggdrasil, X-Node and the root helper, writes the configuration and prints the web address and the administrator password. It also asks whether the DNS server should be enabled and creates the first invite. The credentials are saved to /root/x-node-credentials.txt.

What it offers

  • SOCKS5 over TCP and UDP, so DNS and QUIC work as well.
  • Client registration with one-time invites, QR codes and links.
  • Per-client labels, access, daily and monthly quotas, speed limits.
  • Traffic accounting that survives restarts.
  • Automatic public Yggdrasil peers, plus peers pinned by hand.
  • Web interface and a full CLI.
  • Optional Alfis DNS server for Yggdrasil names.

Command line

The same operations are available in a shell. Every command accepts -config PATH.

  • x-node status — configuration and live counters.
  • x-node invite — new invite, QR code and link.
  • x-node allow list, allow add, allow remove — the allowlist.
  • x-node allow link ADDRESS — QR code for a client that is already allowed.
  • x-node clients, x-node usage — who is connected and how much traffic they used.
  • x-node quota show, quota set, quota reset — limits.
  • x-node peers — public peer state; peers refresh re-checks them.
  • x-node dns status, dns on, dns off — the DNS server.
  • x-node web url, web password — the panel address and password.
  • x-node doctor — installation checks with hints.
  • x-node update check, update upgrade — releases.

X-Node web interface

The panel is served below a random path and protected by a login. The address is printed by x-node web url and by the installer.

Dashboard

Four counters on top: the Yggdrasil address, the number of clients, the traffic today and this month. The traffic chart follows them. Below it are two cards: X-Node on the left and Yggdrasil on the right, with the DNS server card directly under Yggdrasil. The Yggdrasil address and the peer link stay on one line without wrapping; a value wider than the card scrolls sideways.

The traffic chart covers 15 minutes, 1 hour, 6 hours or 24 hours. The right-hand column holds:

  • X-Node — service state, SOCKS5 and API ports, access mode, connection limits, UDP relay, IPv6 outbound, paths.
  • Yggdrasil — version, public key, routing entries, subnet, peers and the peer link.
  • DNS server — the Alfis state, listen address, the Alfis web password and a link that opens the Alfis panel in a new tab.

System Info and Update share the next row, then Quotas and Web interface, and the peer table closes the page.

Clients

The registered clients with their address, device name, app version, live TCP and UDP counters, traffic and quota. The six actions of a row are arranged in two rows of three on a desktop; on a tablet the table turns into cards.

  • Edit — label, notes and per-client limits.
  • QR / link — show the code that adds this exit to the phone again.
  • New token — invalidate the old API token and issue a new one.
  • Disconnect all — close the open TCP and UDP sessions.
  • Suspend — keep the client in the list but refuse new connections.
  • Remove — take the address out of the allowlist.

Invites

An invite is a one-time secret. Set how many devices may use it and how long it stays valid, then show the QR code or copy the yggnode:// link. The token is stored on the server, so the code can be shown again later.

Configuration and Logs

Configuration shows config.json, yggdrasil.conf and alfis.conf with their full paths. The editor validates a file before saving and keeps a backup. Listener changes need a restart; the tab has the buttons for x-node, yggdrasil and the DNS server.

Logs shows the latest service lines. Wrap lines is on by default; turn it off to read a stack trace without wrapping. Auto refresh polls every three seconds. The Help entry in the sidebar under Logs opens this guide in a new tab.

DNS server

X-Node can run Alfis as a separate service, x-node-dns.service. It answers DNS queries for the clients of the exit and is reachable only through Yggdrasil, on the Yggdrasil address of the server.

What Alfis answers

  • Names inside Yggdrasil, including .ygg, from its own distributed zone.
  • Ordinary names, forwarded to the configured upstream resolvers (two Quad9 addresses by default).
  • Names are cached in memory; the cache limit is 100 MB by default.

How to turn it on

  1. Open Settings → DNS server and enable the switch, then press Save.
  2. The server generates the Alfis web password if it is empty, writes /etc/x-node/alfis.conf, installs the unit and starts it.
  3. The dashboard card turns to running. The Open Alfis web UI button opens the panel through the dashboard address, at /<random>/dns/; log in with the password from the card. The panel is also reachable directly at http://ADDRESS:8082/ over Yggdrasil.

The same switch is available in the shell: sudo x-node dns on and sudo x-node dns off. Turning it off stops the unit but keeps the password and the zone data.

Release archives bundle Alfis with its web UI. If an upstream nogui binary is installed instead, DNS still works, but the unit does not pass --web-ui and the panel link is hidden.

What the clients see

When the server is on, Y-Node discovers it through the exit node and lists it under Settings → DNS → Available servers with the note DNS from exit node. The address is the Yggdrasil address of X-Node and port 53, unless the installer chose another port.

The operator of the exit can make it the default for a profile with the DNS exit node switch in the Y-Node exit settings. The server then appears under IN USE with a lock: it cannot be removed by hand while the switch is on.

Ports and files

  • dns.listen — resolver address, by default the Yggdrasil address on port 53.
  • dns.webListen — Alfis web interface, by default the Yggdrasil address on port 8082. It speaks plain HTTP and is not exposed to the clearnet.
  • /etc/x-node/alfis.conf — generated Alfis configuration. Edit it through the Configuration tab or the settings; manual edits are replaced on the next sync.
  • /var/lib/x-node-dns — Alfis state: keys, zone data and cache.
  • dns.forwarders — upstream resolvers for ordinary names.

Y-Node

Y-Node is the Android client. Install the APK for the device architecture (arm64-v8a for most phones, armeabi-v7a for older 32-bit devices), open the app and allow the VPN permission.

Tabs

  • Tunnel — connect and disconnect, your Yggdrasil address and key, live traffic, latency, the exit node card and the failover state.
  • Peers — the peers in use, the replacement pool, peer discovery with latency ranking, and manual peer addresses.
  • Address book — a catalogue of Yggdrasil sites and services, with search and your own entries.
  • Apps — per-app routing: choose which apps use the tunnel and which stay on the mobile network.
  • Settings — connection, DNS, network, power, logs, appearance, updates and about.

Adding an exit node

  1. On X-Node create an invite: sudo x-node invite or the Invites page.
  2. In Y-Node open the exit node card and press Add an exit node.
  3. Scan the QR code, paste the yggnode:// link, or enter the address and ports by hand.
  4. Activate the profile. The app registers the device, receives an API token and checks the exit.

A profile can also be added as a plain SOCKS5 proxy with only the Yggdrasil address and port. Such a profile is marked SOCKS5; it can be upgraded later with an invite or a token.

The exit card

The card shows the state — Online, Connecting, Degraded, Direct fallback, Not allowed, Unreachable — and the round-trip time. It also shows the quota and speed limits reported by the server, and the IPv6 state of the exit.

Several profiles form a failover list: when the active one stops answering, the app tries the next. A profile can be checked on demand with Check now.

Logs

Settings → Logs opens the event log of the app and the Yggdrasil node. The same screen can copy or share the log for a bug report. Connection stages — permission, tunnel, peers, first answer — are shown on the Tunnel tab while the app connects.

DNS in Y-Node

Settings → DNS decides how the phone resolves names while the tunnel is up.

ModeBehaviour
YggdrasilQueries go to DNS servers reachable inside Yggdrasil. .ygg names resolve, and the exit node's DNS server can resolve ordinary names as well. Choose this mode to use the DNS server of the exit.
SystemThe phone keeps its own DNS. .ygg names are still resolved by the built-in resolver; ordinary names go to the mobile or Wi-Fi resolver.

IN USE and Available servers

IN USE lists the servers that are actually queried, in order. Available servers holds the presets and the servers discovered from the network. Add server accepts an IPv6 address inside Yggdrasil.

A server can show Not working: the app could not get an answer from it. The check runs in the background and does not block the tunnel.

DNS from the exit node

When X-Node runs the DNS server, Y-Node adds it to Available servers automatically, marked DNS from exit node. It is the Yggdrasil address of the exit on port 53.

The DNS exit node switch in the exit profile settings puts that server into IN USE and locks it with a lock icon: while the switch is on, the server cannot be removed by hand. Turn the switch off to manage the list yourself.

Exit DNS servers

In the exit profile settings, Exit DNS servers are the resolvers the phone uses while traffic goes through that exit. They are separate from the DNS mode: the mode decides whether Yggdrasil DNS is used at all, the exit list decides which addresses are asked. A server learned from the exit is added to this list and can be kept per profile.

How DNS finds the exit

The DNS server is advertised by the exit itself, so there is nothing to copy between the two machines.

Checklist

  1. On X-Node, x-node dns status says the server is on and the unit is active.
  2. The dashboard DNS card shows running, and the Alfis web UI opens from the button.
  3. In Y-Node, the exit profile is active and the card says Online.
  4. The DNS mode is Yggdrasil, and the server appears under Available servers with the DNS from exit node note.
  5. Turn on DNS exit node in the exit settings to put it under IN USE.
  6. Open a .ygg site and an ordinary site to check both paths.

Troubleshooting

The DNS card says stopped

  • The helper is not installed: the card shows the error. Run install.sh again.
  • Alfis is missing: the card says Alfis is not installed. Turn the DNS server on again: X-Node downloads and installs Alfis by itself. The installer adds the binary too.
  • The unit failed: journalctl -u x-node-dns -n 50 shows why. Port 53 may already be taken by another resolver.

The client cannot register

  • The invite is used up or expired: create a new one.
  • The phone is not connected to Yggdrasil: check the Tunnel tab.
  • The exit is unreachable: check the peer link and x-node status.
  • Registration is disabled in X-Node Settings → Access.

Ordinary names do not resolve

  • The DNS mode is System: switch to Yggdrasil to use the exit resolver.
  • The exit DNS server is off, or its forwarders are unreachable.
  • The server is not in IN USE: add it or turn on the exit switch.
  • UDP is blocked on the path: X-Node Settings → UDP relay must be on.

The panel does not open

  • Use the exact address from x-node web url, including the random path.
  • The public URL depends on the nginx and firewall choices from the installer.
  • Too many failed logins block the address for 15 minutes by default.

Security notes

  • The Yggdrasil private key is the identity of a node. Anyone who has it can use its address; keep it out of backups that are shared.
  • An invite is a one-time secret. Treat the QR code like a password and revoke unused invites.
  • Open mode disables the allowlist and quotas. Leave it off on a public exit.
  • The Alfis web interface has its own password. It is stored in dns.webPassword and shown on the dashboard; change it if it leaks.
  • The panel is protected by a login and a random URL path, but it is not a replacement for HTTPS. Publish it through nginx with a certificate when it is reachable from the Internet.
  • Yggdrasil hides the traffic from intermediate nodes, but the exit node sees the destinations. Run your own exit or trust its operator.
